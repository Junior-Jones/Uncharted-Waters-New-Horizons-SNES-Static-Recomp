Rock n' Roll Racing
-------------------
Examined Temp/04-RockNRR-V10.2-Work and GitHub/
Rock-N-Roll-Racing-SNES-Static-Recomp-Source.
runtime/v10_2_apu.cpp synchronizes the compiled APU to guest master time and
registers sc_static_apu_set_sink. frontend/windows/rnr_app_core.c installs
audio_sink, which appends stereo samples into the bounded adapter ring and
counts any dropped old frames. During native instruction execution its
advance_frames invokes the output callback every16384 instructions. The
launcher calls pump_progress inside that callback and the full pump at frame
completion. The backend consumes only queued native PCM, resamples, applies
volume and submits to DirectSound. Device queue control is host-owned.

Jungle Strike
-------------
Examined Temp/compact-source-candidate-1.0.0 plus GitHub/Source code.
runtime/v10_33_dsp.c publishes native stereo PCM with knownness into its core
FIFO, fails closed on overflow and exposes a consuming read operation.
runtime/v10_40_core_api.c invokes its streaming callback when at least128 PCM
frames are available during the instruction loop. frontend/windows/
jungle_app_core.c stream_audio_progress drains core PCM into the adapter ring
BEFORE invoking the frontend output callback. The launcher/backend then pump
that partial batch; end-of-frame latency control is separate. This behavior is
present in both examined Temp candidate and GitHub source, not just a comment.

Gundam Wing
-----------
Examined Temp/Native-Final-Source-20260906 plus GitHub/
Gundam-Wing-Endless-Duel-SNES-Static-Recomp-Source.
static-core/src/sdsp_clock_current.c publishes timestamped stereo/knownness
frames into a4096-frame ring with a monotonic total-frame index. The Temp and
GitHub clock-owner files have identical SHA256:
5bf6f1d3faf53085b7c83f8be42a181a0eaefb5b7a4376ac1c09ddde6c23482d.
static-core/src/core_api.c exposes indexed PCM reads. frontend/common/
gundam_w_host_core.c owns a separate read index and advances it only after
successful reads. frontend/windows/gundam_w_app_core.c drains batches up to
1024 frames into its bounded adapter FIFO after a natural frame, then invokes
the frontend pump. It is NOT the same in-frame128-sample interface as Jungle.
The runtime/README.md is historical; the current audio owner is static-core/.

Historical New Horizons comparison and decision
-----------------------------------
Its native DSP and adapter each have an8192-frame consuming FIFO, not Gundam's
indexed core history and not Rock's direct sink. Its original streamed API
pumped only after the complete frame. The first16384-step patch borrowed
Rock's cadence but did not reproduce Jungle's PCM-ready boundary and did not
fix user-audible playback. Do not label it successful.

Implemented in target-owned source: opaque streamed core call, invoking
the host-output callback when128 native PCM frames are ready at an instruction
boundary. Adapter transfers those samples before frontend submission. The
existing unstreamed call passes no callback and retains its prior loop/limit.
Callbacks are ephemeral and may drain PCM only, not mutate/advance guest state.
Remaining partial PCM is transferred at the normal frame boundary.
